# ST7796S 横屏改造手册

> 适用：CH32V307VCT6 + ST7796S 320×480（FSMC 8080）+ LVGL 8 + GT911
> 目标：把 320×480 竖屏改成 480×320 横屏
> 结论：**改 4 处 + 重排 1 次界面**，其中触摸坐标那处最容易漏

---

## 0. 改动总览

| # | 文件 | 位置 | 改什么 | 必须 |
|---|---|---|---|---|
| 1 | `HAL/LCD/lcd.h` | 第 51 行 | `LCD_DFT_DIR` 换成横屏枚举 | ✅ |
| 2 | `LVGL/GUI/lvgl/examples/porting/lv_port_disp_template.c` | 第 33~34 行 | `HOR_RES / VER_RES` 换 480 / 320 | ✅ |
| 3 | `User/ui/theme.h` | 第 36~37 行 | `UI_W / UI_H` 换 480 / 320 | ✅ |
| 4 | `LVGL/GUI/lvgl/examples/porting/lv_port_indev_template.c` | 第 129~133 行 | 触摸坐标交换 | ✅ |
| 5 | `User/ui/*.c` | 各页面 | 按 480×320 重排布局 | ✅ 否则界面挤成一团 |

## 1. LCD 扫描方向（`HAL/LCD/lcd.h`）

### 改这里

```diff
- #define LCD_DFT_DIR             LCD_DIR_R2L_U2D    /* 默认方向 320x480 */
+ #define LCD_DFT_DIR             LCD_DIR_U2D_L2R    /* 0x20 横屏 480x320 */
```

### 为什么只改这一行就够

`lcd.c:294` 的 `lcd_set_dir()` 里有这段：

```c
if(((dir >> 4) % 4) != 0)          /* bit4/bit5 = MV/MX，决定行列是否交换 */
{
    lcddev.width  = LCD_PANEL_HEIGHT;   /* 480 */
    lcddev.height = LCD_PANEL_WIDTH;    /* 320 */
}
else
{
    lcddev.width  = LCD_PANEL_WIDTH;    /* 320 */
    lcddev.height = LCD_PANEL_HEIGHT;   /* 480 */
}
...
lcd_write_cmd(0x36);                        /* MADCTL */
lcd_write_data((uint16_t)(0x08 | (uint8_t)dir));   /* 0x08 = BGR */
```

`lcd_init()` 第 265 行和 `lcd_panel_init()` 第 195 行都调了 `lcd_set_dir(LCD_DFT_DIR)`，
条件 `s_lcd_ready || dir == LCD_DFT_DIR` 成立，所以寄存器会真的写下去。

于是 `lcddev.width/height` 自动变 480/320，`lcd_clear` / `lcd_fill` / `lcd_show_string`
这些基于 `lcddev` 的函数全部跟着生效 —— **驱动逻辑一行都不用动**。

### 4 个横屏枚举怎么选

| 枚举 | 值 | 效果 | 选错时的现象 |
|---|---|---|---|
| `LCD_DIR_U2D_L2R` | `0x20` | 标准横屏（推荐先试） | — |
| `LCD_DIR_U2D_R2L` | `0x60` | 上下对、左右反 | 画面水平镜像 |
| `LCD_DIR_D2U_L2R` | `0xA0` | 上下反、左右对 | 画面垂直镜像 |
| `LCD_DIR_D2U_R2L` | `0xE0` | 180° | 整个倒过来 |

判断依据：`(dir >> 4) % 4 != 0` 才有宽高交换。0x20/0x60/0xA0/0xE0 都满足，0x00/0x40/0x80/0xC0 是竖屏。

## 2. LVGL 分辨率与缓冲（`lv_port_disp_template.c`）

### 改这里

```diff
- #define MY_DISP_HOR_RES     320
- #define MY_DISP_VER_RES     480
+ #define MY_DISP_HOR_RES     480
+ #define MY_DISP_VER_RES     320
  #define MY_DISP_BUF_LINES   10
  #define MY_DISP_BUF_SIZE    (MY_DISP_HOR_RES * MY_DISP_BUF_LINES)
```

`MY_DISP_BUF_SIZE` 会自动从 `3200` 变 `4800`，不用手改。

### 内存变化

| | 竖屏 | 横屏 |
|---|---|---|
| 单缓冲 | 320×10×2B = 6.4 KB | 480×10×2B = 9.6 KB |
| 双缓冲合计 | 12.8 KB | **19.2 KB** |
| 差值 | | **+6.4 KB** |

RAM 紧张就把 `MY_DISP_BUF_LINES` 从 10 降到 8：
`480×8×2×2 = 15.4 KB`，只比原来多 2.6 KB，刷屏略碎一点，肉眼基本看不出。

`lcd_dma_init()` 里 `DMA_BufferSize = MY_DISP_BUF_SIZE` 是宏，自动跟着变，不用改。

## 3. 主题尺寸（`User/ui/theme.h`）

```diff
- #define UI_W             320
- #define UI_H             480
+ #define UI_W             480
+ #define UI_H             320
```

### 好消息

UI 层**没有硬编码 320/480**。已确认这些文件全用 `UI_W / UI_H`：

- `common.c` — `ui_title_bar()`、`ui_hint_bar()` 都是 `UI_W - 24` / `UI_H - 46`
- `menu_ui.c` — `UI_W - 60`、`UI_W - 24 - 56`
- `boot_ui.c` — `lv_obj_set_size(s_scr, UI_W, UI_H)`
- `task_example_ui.c` — `UI_W - 32`

所以改这两个宏，**标题栏和提示条会自动铺满新宽度、贴到新底部**。

### 但布局还得重排

原来按竖屏摆的坐标（`title=56`、卡片 `y=76 h=200`、按钮 `y=292`）在 320 高的屏上会溢出：
`292 + 46 = 338 > 320`，按钮直接压到提示条外面。

横屏可用区域：`y = 56 ~ 280`（标题 0~56、提示 280~320），只有 **224px 高**。

重排建议：
- 上下结构 → 改成左右分栏（左侧放数值卡，右侧放图表）
- 或者用设计器的「方向 → 横 480×320」重新画一版

## 4. 触摸坐标（`lv_port_indev_template.c`）—— 最容易漏

### 现状

```c
static void touchpad_get_xy(lv_coord_t * x, lv_coord_t * y)
{
    (*x) = gt911_touch.point[0].x;      /* 0 ~ 319（物理竖装） */
    (*y) = gt911_touch.point[0].y;      /* 0 ~ 479 */
}
```

原样透传。LVGL 现在按 480×320 收，**点哪儿都不准**（手指在左上，LVGL 认为在中上）。

### 改成

```c
static void touchpad_get_xy(lv_coord_t * x, lv_coord_t * y)
{
    lv_coord_t tx = gt911_touch.point[0].x;   /* 0 ~ 319 */
    lv_coord_t ty = gt911_touch.point[0].y;   /* 0 ~ 479 */

    /* 横屏：竖屏坐标 -> 横屏坐标（对应 LCD_DIR_U2D_L2R / 0x20） */
    (*x) = ty;
    (*y) = (lv_coord_t)(GT911_SCREEN_WIDTH - 1 - tx);   /* GT911_SCREEN_WIDTH = 320 */
}
```

### 4 组映射对照（LCD 方向定了，就只试这 4 组）

| LCD 方向 | `*x` | `*y` |
|---|---|---|
| `0x20` | `ty` | `319 - tx` |
| `0x60` | `479 - ty` | `tx` |
| `0xA0` | `479 - ty` | `319 - tx` |
| `0xE0` | `ty` | `tx` |

> `GT911_SCREEN_WIDTH / HEIGHT`（`GT911.h:40-41`）**不要改**。
> 它们代表触摸面板的物理分辨率（竖装 320×480），改了公式就错。

## 5. 验证顺序（务必分步，别一次全改）

### 第 1 步：只改 LCD 方向

烧进去，临时把 `lcd.c:273` 的 `lcd_clear(LCD_COLOR_BLACK)` 换成 `LCD_COLOR_RED`。

- 整屏红 → 方向对了，继续
- 只红一半 / 花屏 → 换另外 3 个枚举值再试

改完记得换回黑色。

### 第 2 步：改 LVGL 分辨率

此时菜单页应该铺满整屏，但布局还是竖屏的，会挤在一起 —— **正常现象**。

- 铺满 → 继续
- 只有左上角一块、右下黑 → 分辨率没改对，检查 `HOR_RES / VER_RES`
- 有黑边 → `hor/ver` 写反了

### 第 3 步：改 `theme.h` + 重排界面

标题栏、提示条应该自动到正确位置；中间的内容按 480×320 重新摆。

### 第 4 步：改触摸

点一个按钮 / 拖一下滑条：

- 点得准 → 完成
- 整体错位 → 换映射组（4 选 1）
- x/y 反了 → 公式第一行和第二行对调
- 只能点到一角 → 公式里减的常数不对（用 319 / 479，不是 320 / 480）

## 6. 排错速查

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 只有左上角有图像，其余黑 | LVGL 还是 320×480 | 改第 2 处 |
| 画面整体倒过来 | MADCTL 选错 | 换 `0x60` / `0xA0` / `0xE0` |
| 画面被水平/垂直镜像 | MADCTL 选错 | 同上 |
| 图像撕裂、刷新慢 | DMA 缓冲太小 | `BUF_LINES` 提到 12 或降回 8 试 |
| 花屏、颜色不对 | 0x08（BGR）位丢了 | 检查 `(0x08 \| dir)` 没被改 |
| 编译报 RAM 不足 | 双缓冲 19.2KB | `BUF_LINES` 降到 8 |
| 图像正常但点不准 | 触摸没做映射 | 改第 4 处 |
| 触摸只能点到屏幕一角 | 公式常数用了 320/480 | 改成 319/479 |
| 触摸 x/y 互换 | 映射缺第一行 | 按表补 |
| 界面元素挤在一起 | 布局没重排 | 按 480×320 重画 |
| 提示条跑到屏幕外 | `theme.h` 没改 | 改第 3 处 |

内存余量可以在 msh 里敲 `menu` 看（`menu.c` 的 `menu_cmd` 会打印 heap 和 LVGL 剩余）：

```
menu : page=TASK, task=MICLUX, cursor=0, lost=0
heap : used=12345 free=50000
lvgl : free=40000 biggest=38000 frag=3%
```

`lvgl: free` 至少要留几 KB，不然加一个页面就 `ui_page_create() == NULL`（白屏）。

(*x) = gt911_touch.point[0].x;

## 8. 不要改的东西

| 宏 | 位置 | 为什么不能改 |
|---|---|---|
| `LCD_PANEL_WIDTH / HEIGHT` | `lcd.h:34-35` | 面板物理尺寸，驱动靠它算交换后的宽高 |
| `GT911_SCREEN_WIDTH / HEIGHT` | `GT911.h:40-41` | 触摸面板物理分辨率，公式里要用 |
| `LCD_EXPECT_ID` | `lcd.h:36` | ST7796S 的 ID，改了会报 ID 读取异常 |
| `anime.c` 的 `T_LIST 320` | `anime.c:37` | 动画位移量，不是屏幕尺寸（横屏下略大，无碍） |

## 9. 运行时切换（进阶，不建议）

`lcd_set_dir()` 可以在运行时调，但 LVGL 的 `hor_res / ver_res` 是注册驱动时定死的，
想动态切必须：

1. `lv_disp_drv_t` 里改 `hor_res/ver_res` 并重新 `lv_disp_drv_update()`
2. 重新算 `draw_buf` 大小
3. 所有页面重建

实际做下来不如直接改宏 + 重新烧写省事。**建议编译期定死方向。**

## 10. 配合设计器

`tools/ui_designer.html` 顶部「方向」下拉切到 **横 480×320**，画布会变成横屏比例：

- 标题栏 / 提示条自动按新宽度重排
- 超出画布的控件自动夹回边界
- 生成的代码坐标直接可用

设计好后「下载 .c」，替换 `User/ui/task_xxx_ui.c` 即可。
注意生成代码里的 `UI_W / UI_H` 引用会自动跟随 `theme.h`，不用手改。
