快速上手

User/tool/

用户头文件目录 User 已经在编译器的 -I 里了，所以直接写 tool/tool.h 即可。

/* 1. 一处 include，十二个模块全带走 */
#include "tool/tool.h"

static int32_t  s_lux;          /* EMA 状态 */
char buf[16];                 /* 数字转字符串的落脚点 */
static tool_timer_t s_t;        /* 软件定时器 */
static tool_range_t s_rng;      /* 曲线量程 */

void tick(uint32_t now)
{
    /* 2. 采样 + 平滑 + 攒量程 */
    s_lux = tool_ema_step(&s_lux, veml7700_lux_get(), 3);
    tool_range_add(&s_rng, s_lux);

    /* 3. 1 秒一次（替代 ++div 计数） */
    if(tool_timer_tick(&s_t, now))
    {
        tool_fx_str(buf, sizeof(buf), s_lux * 10, 1);   /* 123 -> "12.3" */
    }
}

照抄就能跑

工具箱的价值在"拼起来用"，这三套正好对应你工程里已有的场景。

配方 A · 传感器曲线自动量程

tool_plot.h + tool_filter.h + ui/common.h 的 ui_plot_t
  • 逻辑线程只攒 min/max（tool_range_add），不碰 lv_。
  • UI 线程算"好看"的上下限（tool_range_auto），只有变了才调 ui_plot_line()。
  • 照度从 30 lux 跳到 3000 lux，纵轴自动从 0~40 换到 0~4000，曲线不会被压成一条线。
/* 逻辑线程 */
tool_range_add(&s_rng, lux);

/* UI 线程（render 里） */
int32_t lo, hi;
tool_range_auto(&s_rng, 4, &lo, &hi);
if((lo != s_lo) || (hi != s_hi))
{
    s_lo = lo; s_hi = hi;
    ui_plot_line(s_plot, 1, &(ui_plot_line_t){
            .color = 0xFFA300, .width = 2, .vmin = lo, .vmax = hi });
}

配方 B · 非阻塞节拍

tool_timer.h
  • 现在 task_example.c 里是 if(++s_div_b >= 100)：改周期要改宏，tick 不准还会累积误差。
  • 换成时间戳比较：周期随手改，线程被卡一下也不会补发一串。
/* 需要更快的曲线？把 1000 改成 40 就是 25Hz，不用动别的地方 */
if(tool_timer_tick(&s_beat, now, 1000))
{
    ch422_show_number(--count);
    beep_freq_set(2000);
}

配方 C · 串口帧收发

tool_crc.h + tool_fmt.h + tool_bit.h
  • 发：tool_crc16_modbus() 追加两字节，低字节在前。
  • 收：整帧算一遍对比；不一致直接丢，别进状态机。
  • 调试：tool_bytes_str() 把帧打成 AA 55 03 01 这种样子丢给 rt_kprintf。
uint16_t c = tool_crc16_modbus(frame, n);
frame[n]     = (uint8_t)(c & 0xFF);
frame[n + 1] = (uint8_t)(c >> 8);

char line[48];
tool_bytes_str(line, sizeof(line), frame, n + 2);
rt_kprintf("tx: %s\r\n", line);      /* tx: AA 55 03 01 37 4B */

配方 D · 屏上画一段波形（赛题 6）

tool_wave.h + tool_draw.h + ui/common.h
  • 先把一个周期算成采样点：tool_wave_fill_sin/PWM 直接填 DAC 码值。
  • 画到屏上用 tool_line_each 把相邻两点连起来，比 256 次 set_px 只多一点点点密度。
  • 要"至少 2 个周期"就把 x 轴按 2 个周期铺满，频率变了只改采样点数，不动坐标。
/* 一个周期 100 点，画 2 个周期 */
uint16_t w[100];
tool_wave_fill_pwm(w, 100, 30, 4095, 0);

for(i = 0; i < 100; i++)
{
    int16_t y = tool_map(w[i], 0, 4095, y_bottom, y_top);
    if(i) tool_line_each(x0, y0, x0 + 2, y, put_px, canvas);
    x0 += 2; y0 = y;
}

约定与坑

先看这张表
约定说明
全部 static inline没有 .c 文件，所以每处 include 都会各自内联一份。没调用到的函数编译器直接丢掉，不占 Flash。
只用 <stdint.h>不 include rtthread.h、不碰 HAL，任务线程 / UI 线程 / 中断里都能调。
带状态的四个结构体tool_ma_t、tool_hyst_t、tool_range_t、tool_timer_t 不是线程安全的，别让两个线程共用一个实例。
整数溢出边界tool_map()：输入跨度 × 输出跨度 < 2^31；tool_pct_u32()：part < 4200 万。ADC / 计数场景远达不到。
源文件编码本工程是 GBK + CRLF。User/tool/*.h 已按这个编码写好，用别的编辑器另存时注意别改成 UTF-8。
时间基准tool_timer.h 不绑定 OS：传进来就行。RT-Thread 用 rt_tick_get_millisecond()，裸机用 1ms 自增的 uint32_t。
