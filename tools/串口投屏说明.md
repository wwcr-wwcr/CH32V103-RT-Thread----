# task6 串口投屏（16 色 · 目标 1 秒 1 帧 · 不带声音）

电脑抓屏 → 缩到 320×460 → 量化成 16 色 → 切成 32×32 块，每块 4bit 索引 + PackBits 压缩
→ 串口 → 板子 LCD 显示。

---

## 一、为什么是 16 色（这张表决定了所有设计）

| 方案 | 全屏数据量 | 921600bps 下一帧 |
|---|---|---|
| RGB565 原始 | 300 KB | 3.3 秒 |
| RGB565 + RLE | 60~150 KB | 0.7~1.6 秒 |
| **4bit 索引（16 色）** | **73.6 KB** | **0.8 秒** |
| **4bit + PackBits（本方案）** | **20~40 KB** | **0.2~0.5 秒** |

4bit 直接把数据砍到 1/4，PackBits 再按字节游程压一半左右。
画质是色块化的，但布局、窗口、文字位置都认得出来 —— 符合"看个大概"。
调色板每帧自适应（PC 端用中位切分出 16 色），所以颜色不会糊成一片。

## 三、怎么跑

1. MounRiver 里 **F5 刷新**（新增了两个 .c，不刷新 IDE 不编译它们），编译烧写；
2. 板子进菜单 → **STREAM** → K3 进入；
3. 电脑装依赖：
   ```
   pip install pyserial mss pillow
   ```
4. 先自检，不连硬件也能跑，会打印压缩率：
   ```
   python tools/pc_streamer.py --dry-run
   ```
5. 正式投屏：
   ```
   python tools/pc_streamer.py --port COM5 --baud 921600
   ```
   竖屏想横着看：`--rotate 90`；不想变形：默认 `--fit contain`
6. **先 Ctrl+C 关脚本，再按 K4 退出**。

状态栏显示：`12.3K/s t1234 d0 e0` = 接收速率 / 累计块数 / 丢弃块数 / 解压失败块数。

## 四、协议

```
 0   0xA5
 1   0x5A
 2   type            01=画面块 02=声音(已停用) 03=控制
 3   len 低字节
 4   len 高字节
 5   crc8(type, len_lo, len_hi)     多项式 0x07，初值 0
 6.. payload
 n   crc16 低字节                   多项式 0x1021，初值 0xFFFF，只算 payload
 n+1 crc16 高字节
```

**画面块 payload**：`x(2) y(2) w(1) h(1) fmt(1) + PackBits 数据`，坐标小端，`fmt=0`。

**控制 payload**：
- `0` 清屏
- `1` + 32 字节 = 16 个 RGB565 调色板（小端）。**必须先发调色板再发块**，
  否则这一帧的颜色是上一帧的。

**PackBits**（每一块独立压，板子 512 字节一格全部装得下）：
```
控制字节 c:
  c < 0x80   后面跟 c+1 个原样字节（1~128）
  c >= 0x80  后面 1 个字节重复 (c&0x7F)+3 次（3~130）
```
压缩前是半字节流：两个像素拼一个字节，高的那个在前。

## 五、"只有一个串口"怎么解决

uart1 平时是控制台（rt_kprintf + msh）。进 STREAM 后：

1. **关 RXNE 中断**，DATAR 只归 DMA 读（否则 DMA 和中断抢同一个寄存器，丢字节）；
2. **静音 rt_kprintf**：驱动里的 `ch32_putc()` 在流模式下直接返回。不静音的话 ASCII 会
   插进二进制流破坏帧，而且它是**死等 TC 标志**的，921600 下一行日志要 1.4ms；
3. **改波特率**到 `T6_BAUD`（默认 921600）。

代价：这期间 msh 收不到命令。退出时全部还原（波特率回 115200）。

## 六、缓存堆积的四道闸

| 层级 | 做法 |
|---|---|
| 硬件 | DMA1_Ch5 **循环模式**，512B 转圈搬，CPU 只在半满/装满/空闲时进一次中断 |
| 驱动 | 4KB 环形缓冲，**满了丢字节 + 置 resync** 重新找帧头，中断里绝不等待、不 malloc |
| 应用 | 图块队列只有 **8 格**，显示跟不上就**丢新块**（不排队）。一帧 150 块，10ms 能吐 8 块 = 800 块/秒，线路最多喂 45 块/秒，正常永不丢 |
| PC | 一帧发完再抓下一帧，用**阻塞写**让线路自己给节奏，不在 Python 里堆 |

CRC16 保证坏帧不会污染后面的数据；`e` 计数一直涨说明解压数据坏了（线材/波特率问题）。

## 七、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 全黑，状态栏也没字 | 没进 STREAM 页面 / 波特率不一致 / 串口名写错 |
| 状态栏显示 `ERR` | `uart1` 打不开 |
| 一块一块花屏，`e` 猛涨 | 波特率太高或线材差 → 两边一起降到 460800 |
| 颜色全部偏色/发灰 | 调色板帧丢了。PC 端每帧都会重发，等一帧就好 |
| 画面闪 | 每帧整屏重画，正常。想看更连贯就把波特率提到 1500000 |
| 退出后 msh 全是乱码 | 关脚本顺序反了，重开串口监视器即可 |

想更快：把 `task_6.c` 的 `T6_BAUD` 和脚本 `--baud` 一起改成 `1500000` 或 `2000000`
（CH343/CP2102 一般支持，老 CH340 只到 921600）。
