
## 设计器「同步 task」修好 + 导入时自动对齐前缀

### 问题
`patchTask()` 用一条全局正则
`/(?<!void\s)([A-Za-z_]\w*_ui_render)\s*\([^;]*?\)\s*;/g`
其中 `[^;]*?` **允许跨行**：模板注释里的 `xxx_ui_render(s_c)` 和下一行真实调用的 `;`
会凑成一次匹配，连注释的结束符一起吃掉 → `task_render()` 整个函数被注释掉。
另外替换用的是设计器当前前缀，导入的 task 名和前缀不一致时会生成 `app_ui_render(a);`
这种不存在的函数名。

### 修法（tools/lvgl_designer.html）
1. `patchTask()` 改成**逐行**处理：
   - 空行 / `/*` / `*` / `//` 开头的行原样放过（不再可能跨行）
   - render 调用用 `^(\s*)[A-Za-z_]\w*_ui_render\s*\([^;]*\)\s*;` **锚定行首**
   - `.ui_destroy` 和 `#include` 也改成逐行替换
2. 新增 `applyTaskName(fileName)`：导入 task 时把「文件名前缀」自动设成任务基名
   （`task_veml7700.c` → 前缀 `task_veml7700`），并在状态栏显示同步结果
3. 顺手清掉 `User/task_veml7700/task_veml7700.c` 里那句过时的提示注释

### 实测（node 无头跑真实文件）
- 前缀同步：`task_veml7700.c` → `task_veml7700` ✓
- `*/` 数量不变、行数不变 → 注释没被吃掉 ✓
- 无绑定时：`task_veml7700_ui_render();` ✓
- 有 float 绑定时：`task_veml7700_ui_render(c);` ✓
- `.ui_destroy = task_ui_destroy` ✓ / `#include "task_veml7700_ui.h"` ✓
- 没有 `app_ui_` 残留 ✓

### 坑
JS 块注释里不能出现 `*/` 字面量（我写解释注释时踩了，直接语法错误）。
写成"注释的结束符"就行。

### 遗留
`User/task_veml7700/task_veml7700.c:21` 有个 `static float a` 没用（-Wunused-variable），
UI 的 render 是 `(void)` 无参，要么删掉 a，要么把 a 传给 render。

## 修复 1：VDDA 标定（2026-11-25 下午，用户点名只修两个 bug）

### 背景
之前暴力测试发现：DAC 码值 2048 用万用表量到 **1.80V**（不是 1.65V），
ADC 读 1.65V 输入只有 1513mV（-8.5%）。原因是全工程把 VDDA 当 3.3V 写死。

### 改法（一处定义，全工程引用）
新增 `BSP/vref.c` / `vref.h`：
```c
#define VREF_VDDA_MV_DEFAULT 3666U     /* 实测，不是 3300 */
uint16_t vref_vdda_mv(void);
void     vref_set_vdda_mv(uint16_t mv);   /* 3000..3800 夹住，0 = 恢复默认 */
uint16_t vref_code_to_mv(uint32_t code);  /* 四舍五入 */
uint16_t vref_mv_to_code(uint32_t mv);    /* 钳 4095 */
```
替换点：
- `APP/wave_gen.c` 的 `mv_to_code()` → `vref_mv_to_code()`
- `APP/wave_ana.c` 的 `wave_ana_mv()` → `vref_code_to_mv()`
- `APP/wave_gen.h`：`WAVE_GEN_VREF_MV` 降级为"名义值"，注释说明别再用

新增两条 msh 命令（在 vref.c 里）：
```
vdda            打印当前标定 + code2048/4095 对应 mV
vdda 3666       现测现改
dacv 1650       让 PA5 输出 1650mV（BSP→BSP 调 dac_write，不越层）
```

### 标定值怎么来的
用户万用表实测：码值 **1877 → 1.680V**
→ 满量程 = 1680 × 4095 / 1877 ≈ **3666mV**

### ★ 关键坑：WCH-Link 的串口开关会复位板子
现象：我发完 `dacv 1650`（rc=0、换算正确）再关串口，用户量 PA5 是 0V；
用户自己在 MounRiver 串口终端里敲 `dacv 1650`，就是 1.68V。
原因：WCH-Link 的 COM 口在打开/关闭瞬间拉 DTR/RTS，等于给 RISC-V 一个复位，
DAC 复位值 = 0。**以后凡是要"发命令后人工测量"的验证，必须让用户自己的终端
保持打开，我不去抢 COM5。** 这也解释了上一轮 T5"第一次全 FAIL、过一会儿全 PASS"
的诡异现象（中间被复位悄悄改了状态）。

### 未做（按用户要求只修两个 bug）
`BSP/dac.c:62 write_code()` 轮询 `DMA_GetFlagStatus(TC4)` 但**从不先清 TC4**：
上电后第一次写正常，第二次及以后会在 `dma_start()` 后立刻 `dma_stop()`，
传输可能没落地。**下个任务修：进函数先 `DMA_ClearFlag(TC/HT/TE/GL)`。**

### → 已补（2026-11-25 16:2x，用户点名"加一行 DMA_ClearFlag"）
```c
/* BSP/dac.c write_code() 里，configure_dma 之前 */
DMA_ClearFlag(port == &pa4 ? DMA2_FLAG_GL3 : DMA2_FLAG_GL4);
```
GL 一次清 TC/HT/TE。同时给 `dacv` 的输出加了 `DOR2` 回读：
`[VREF] PA5 <- 1650 mV = code 1843 (DOR2 1843, VDDA 3666 mV) rc=0`
—— 这样"命令返回 0 但输出没变"这类问题，看 DOR2 跟不跟着变就能立刻判断，
不需要万用表。期望码值：1650→1843、3000→3351、500→559、3300→3686。

## 修复 2：任务生成器（tools/new_task.py）+ 重新打包

### 两个 bug
1. `generate()` 里 `"…%s…" % (name, name)` 参数个数不匹配 → 每次运行末尾抛
   `TypeError: not all arguments converted`，退出码 1（文件已生成，只是报错）。
2. `_register_in_menu()` 只认 `^extern const task_t \w+;` 和
   `//****在这里写任务表****//` 两种锚点；menu.c 的锚点改成
   `//extern const task_t task_x;` 之后，**只加了 `&task_xxx`、没加 extern** →
   编译报 undeclared，非常难查。

### 改法
- 格式串改 `% name`
- extern 插入改成三级兜底：①已有 extern 后面 → ②锚点注释后面 →
  ③`static const task_t *const g_app_list[] =` **前面**（保证一定有）
- 找不到 g_app_list 时返回"失败：…"，`generate()` 里单独提示，不再假装成功
- 报告里会写清楚用的哪条路（如 `extern(g_app_list 前)`）

### 实测
- 无 extern 的干净 menu.c → `extern(g_app_list 前) + g_app_list` ✓ 编译通过
- 再来一个 → 插在已有 extern 后面 ✓
- 两个 zdemo 任务链在一起 LINK rc=0，之后已清理、menu.c 已还原
