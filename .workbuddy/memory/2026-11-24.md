
## 大重构：全工程 GBK -> UTF-8（2026-11-24 完成）

用户要求把整个项目转 UTF-8（起因：中文显示乱码，根因就是源码还是 GBK）。

### 范围
只转自己写的代码，第三方库一律不碰：
- 转：User/ APP/ HAL/ BSP/ drivers/（共 74 个 .c/.h）
- 不碰：LVGL/GUI/lvgl、rtthread、Peripheral、Core、Startup、.wvproj、obj
- 自动跳过已是 UTF-8 的（18 个，含 lv_font_song.c / lv_font_my.c）

### 方法
逐文件探测：先 decode('utf-8') 成功就跳过；失败再 decode('gbk') 成功就转；
两个都失败单独列出人工看。结果：**56 个转、18 个跳过、0 个可疑**。
写回 UTF-8 **无 BOM**，换行原样保留 CRLF，只换字节不重排。
备份：`backup_gbk_20261124.zip`（117KB，工程根目录，可整体回滚）。

### 关键坑：HAL/LCD/lcdfont.h 不能直接转
```c
typedef struct { unsigned char Index[2]; unsigned char Msk[24]; } typFNT_GB12;
const typFNT_GB12 tfont12[]={ "中",0x20,0x00,... };
```
`"中"` 是在初始化 `Index[2]`，**GBK 正好 2 字节**；UTF-8 是 3 字节会截断 → 字模表错乱。
处理：把 58 处字模字面量改成 GBK 字节转义 `"\xD6\xD0"`（文件本身保持 UTF-8）。
注释里的中文保留（`/*"中",0*/`），不影响。

### 工具同步（不改就白干）
- `tools/new_task.py`：`save_gbk()` -> **`save_utf8()`**（UTF-8 无 BOM + CRLF），调用点 2 处
- `read_text()` 保持兼容（先 utf-8 再 gbk）
- 任务生成器.exe 已重打包（20:38）
- lvgl_designer.html 不用改（浏览器剪贴板是 Unicode），但 **MRS 的 Workspace 编码要设成 UTF-8**，
  否则新建文件又回到 GBK

## 中文不显示的真正原因：工厂里写死了字体（不是 LV_FONT_DEFAULT）

用户上板后 font 页面汉字空白。排查发现：

`APP/LVGL_DEMO/LVGL_Demo.c` 的 `ui_label_new()`（第 153 行）和 checkbox 工厂（235 行）
原来写死 `lv_obj_set_style_text_font(lbl, &lv_font_montserrat_14, 0);`

**显式 set 的字体优先级高于 LV_FONT_DEFAULT**，所以改 lv_conf 的 DEFAULT 对
所有走工厂创建的控件（= 全部控件，含设计器生成的页面）完全无效 → montserrat 没汉字 → 空白。

之前"全替换"那轮我改过这两行成 UI_FONT_NORMAL，用户回退时代码一起退回去了，
所以这次 fallback 方案又踩同一个坑。

### 已修
两处都改成 `UI_FONT_NORMAL`（theme.h 里 = (&lv_font_cn)）：
- 153 行 label 工厂
- 235 行 checkbox 工厂
现在 User/APP 里 grep 不到任何 lv_font_montserrat_14 引用。
编译：LINK rc=0，FLASH 166568 B（72.62%，和改前一样，只换了符号引用）。

### 验证链（都确认过）
- lv_font.h:241-243 有 `#ifdef LV_FONT_CUSTOM_DECLARE` 机制 → lv_font_cn 全局可见
- lv_conf: MONTSERRAT_14=1 / CUSTOM_DECLARE=LV_FONT_DECLARE(lv_font_cn) / DEFAULT=&lv_font_cn
- lv_font_cn.c:159 `.fallback = &lv_font_montserrat_14`
- lv_draw_sw_letter.c:126 用 g.resolved_font 取位图（回退真的能画）

### 教训
以后加任何"全局字体/主题"类配置，必须同时检查**工厂函数里有没有写死字体**，
否则 DEFAULT 改了也不生效。grep `lv_obj_set_style_text_font` 是最快的检查方式。

## 加中文的工具链：font_scan.py + GUI 补 fallback

### 新增 tools/font_scan.py
扫 User/ + APP/ 的 **字符串字面量**（不是全文！）里的中文，自动生成字库。
```
python tools/font_scan.py             # 扫描 + 生成
python tools/font_scan.py --dry       # 只看字
python tools/font_scan.py --extra "额外字"
```
要点：
- 用 `re.findall(r'"((?:[^"\\]|\\.)*)"')` 先抽字符串再找 CJK，
  **注释不算**（全文扫会得 702 字，只扫字符串是 85 字，差 8 倍体积）
- 自动 union 上一版字库已有的字，保证不丢字
- 固定带 `--lv-fallback lv_font_montserrat_14`

### GUI 补了两个东西（tools/font_gui.py，已重打包）
1. 预设栏加「从工程扫描」按钮 → 直接调 font_scan.scan_chars 填入文本框
2. 参数行加「缺字回退」输入框，默认 `lv_font_montserrat_14`，留空则不加 --lv-fallback
3. run_conv() 加 fallback 参数；--selftest 也带上（size 4537 → 4637 可验证）

打包命令要注意加：`--paths tools --hidden-import font_scan`
（font_scan 是在函数里动态 import 的）

坑：`字体生成器.exe` 正在运行 → PyInstaller 无法覆盖（safe-delete 报 trash 失败）。
先 Stop-Process 关掉再打包。用户当时开了两个实例。

### 补齐字库的结果
- 扫到 **85 个中文字**（上一版只有 10 个）
- lv_font_cn.o = **2265 字节**（约 26.6 B/字，比估算的 34 好）
- FLASH 166568 → **168496 B（73.46%）**，净增 1928
- 字体清单.txt 已重写（85 字全列、来源说明、加字命令、注意事项）

### font_scan.py 增强
- 新增 `read_font_list()`：读 Font 手写区（**只取非注释行**，`#` 后全丢）
- 新增 `write_font_list()`：保住手写区，把"手写区没有的字"重写进自动追加区
- 生成时的字集 = 源码字符串扫到的 ∪ 上一版字库 ∪ Font 清单
- 生成后自动回写 Font → `Font 清单字数 == 字库字形数`（已校验 118 == 118）

### 踩的两个坑
1. `write_font_list` 最初用 `manual = {c for c in head}` 把**注释里的中文也算进手写区**，

2. `obj/` 里出现 **重复定义 `lv_font_my`**：
   `obj/User/lv_font_my.o`（GUI 旧默认输出路径生成的）+ `obj/LVGL/GUI_APP/lv_font_my.o`
   → 链接 `multiple definition`。原因就是字模分散在两个目录。
   处理：删掉 9 个源文件已不存在的孤立 .o，并给 verify_build.py 加了
   "链接时跳过源文件不存在的 .o"（`_rel` 映射 + 检查 .c/.S/.s/.cpp）。
