## 架构现代化：kernel 只管事件，其余全模块化，接口少而厚

用户要求：kernel 只做事件响应 + 分发；其余模块化；接口数量少、每个接口功能多（不是给接口数设上限）。

### 最终模块与接口（对外函数就这些）
| 模块 | 接口 | 说明 |
|---|---|---|
| kernel.h | 3：`kernel_init(处理函数, 渲染函数)` / `kernel_post(类型,编号,值)` / `kernel_run()` | 建队列 + 绑回调 + 10ms 主循环（取事件 -> 回调 -> 渲染回调 -> lv_timer_handler） |
| app.h | 4：`app_init(首页)` / `app_handle(事件)` / `app_render()` / `app_request(应用)` | 任务线程生死、切页、事件分给 on_key/on_set；`app_request(NULL)` = 回首页 |
| event.h | 0（只有 `evt_t {type, code, value}`） | 全系统唯一事件结构，type 0=按键 1=控件 |
| ui/common.h | 控件工厂（不动） | 页面只调 ui_* |
| task/*.c | app_task_t 一张表 | setup/update/on_key/on_set/render/teardown/ui_destroy |

依赖单向：main -> kernel / app -> event.h；kernel 不认识 app（靠 kernel_init 绑回调），app 不认识 kernel（事件是调进来的）。

## 改成"一个任务一条队列"

- `app.c` 里加 `host_t { const app_task_t *task; rt_mq_t q; }`，`s_host` 就是当前任务的上下文。
- 队列在 `app_attach()` 里创建（名字用任务名，深度 4），在 `app_stop()` 里 `rt_mq_delete()`；
  `app_init()` 不再建任何队列，只记首页 + 初始化退出信号量。
- `task_entry()` 的 parameter 从 `app_task_t*` 换成 `host_t*`，从 `host->q` 收事件；
  这样队列归属跟着线程，不用全局 s_q。
- **删掉了 "切页前把队列倒干净" 的 while(rt_mq_recv(...,0)) 循环** —— 每个任务的新队列天然是空的。
- `app` 命令多打一个 `q=on/off`，能看出当前任务的队列在不在。
- 每个任务独立队列之后，"两个线程抢同一条队列"的限制就没了；要同时跑多个任务
  只用把 `s_host` 改成数组（app.h 里写了这句话），事件侧不用再动。
- 验证：9 个源文件零警告，链接通过，FLASH 154564 B (67.38%)。

## 再重构：app 拆成 thread（只管开关），每个 task 自带线程本体

用户判定 app.c 把"线程/事件/切页"揉在一起、只能单开、难扩展，要求：
每个任务（含 menu）自带一套逻辑；app 改成"线程管理"，只管打开、关闭。

### 新结构
| 模块 | 接口 | 职责 |
|---|---|---|
| event.h | 0 | `message {type, code, value}` |
| kernel.h | 2 | `kernel_run(事件入口, 渲染入口)` / `kernel_post(type, code, value)` |
| thread.h | 5 | `thread_init(首页)` / `thread_open(任务,NULL=回首页)` / `thread_wait(ctx,msg,ms)` / `thread_dispatch(msg)` / `thread_render()` |
| task/*.c | 一张 `task_t` 表 | `{ name, stack_size, priority, keep, entry, render, ui_destroy }`，逻辑全在自己文件里 |

- `task_t` 只剩 entry（线程本体）+ render + ui_destroy，setup/update/on_key/on_set/teardown 全部删掉——
  这些现在是任务自己线程本体里的普通函数。
- `thread.c` 有槽位表 `s_slot[4]`（thread/mq/tid/used），支持同时多开；
  `keep=1` 的任务切走时不关线程（后台继续跑自己的循环），`keep=0` 默认切走即关。
- `thread_wait(ctx,msg,ms)` 返回 0 收到 / 1 超时 / -1 该退出；"退出"协议（type=2）只在 thread.c 里出现，任务看不到。
- 切的顺序仍是：开新槽 + 画新页 → 关老线程 → 删老页面（LVGL 不许删当前屏）。
- K4 在 `thread_dispatch()` 里拦下 → `s_want = s_home`。

### 各任务怎么写的
```c
static void lux_thread(void *ctx)      /* 10ms 一拍，自己定 */
{
    lux_setup();
    for(;;) {
        int r = thread_wait(ctx, &msg, 10);
        if(r < 0) break;
        if(r == 0) { 按键/控件处理 }
        lux_update();
    }
    lux_teardown();
}
```
menu 用 `thread_wait(ctx, &msg, -1)` 死等（静态页不空转），K3 里 `thread_open(g_app_list[i])`。

### 顺手修掉的坑
- `kernel_post` 原来没有 `message_q == NULL` 保护（key 线程比 kernel_run 早），已补 + 丢事件计数。
- `app_cmd` 的 printf 少传一个参数（`lost=%lu` 没有对应实参），随 app.c 一起删了。
- `thread_dispatch` 里 `rt_mq_send` 不收 const，拷到局部变量再发。
- 生成的 makefile / verify_build.py 里 app.c → thread.c。

验证：9 个源文件零警告，链接通过，FLASH 154444 B (67.33%)。

## 三改：任务完全自治，thread 退化成 router（纯路由）

用户否掉上一版："slot_body 套了一层，任务只是回调，本质还是 thread 在跑"。
要求任务自己建线程/队列/退出握手，框架只管开/关。选了"每个任务节奏都不一样 → 完全自治版"。

### task_t 变成 5 个回调（不再有 entry/stack/priority）
```c
typedef struct {
    const char *name;
    uint8_t     keep;
    void (*open)(void);                 /* 任务自己建队列+线程+启动 */
    void (*close)(void);                /* 任务自己退出+等收尾+删队列 */
    void (*post)(const message *msg);   /* 任务自己收事件 */
    void (*render)(void);
    void (*ui_destroy)(void);
} task_t;
```

### thread.c/h 删除，新增 router.c/h（4 接口）
`router_init(首页)` / `router_go(任务,NULL=回首页)` / `router_dispatch(msg)` / `router_render()`
- router 里没有一个 rt_thread_create / rt_mq_create，只调 5 个回调。
- 切页顺序仍是：`open()` -> `render()` 一帧（成为当前屏）-> `close()`（keep=0）-> `ui_destroy()`。
  所以 render 必须在 fore_switch 里做，router_render 切完页直接 return，避免同一拍画两次。
- K4 在 router_dispatch 里拦下 → s_want = s_home。

### 任务侧样板（每个任务自带，约 40 行）
`static rt_mq_t s_q; static rt_thread_t s_tid; static struct rt_semaphore s_exit;`
+ `xxx_thread()`（直接当 rt_thread_create 的入口，收 type=2 就 break，末尾 release 自己的信号量）
+ `xxx_open()`（幂等：s_tid != NULL 直接返回）/ `xxx_close()` / `xxx_post()`。
栈和优先级写在任务自己的 open() 里（1024 / 12）。

验证：9 个源文件零警告，链接通过，FLASH 154492 B (67.35%)。MSH：`kernel`（tick/lost）、`router`（cur/home/want/lost）。

## 按键驱动加长按 / 双击（key.c / key.h）

事件编号（key_id_t）：
- 0~3    K1~K4 短按（按下后松开，按住 < 800ms）
- 5~8    K1~K4 长按（按住到 800ms 立刻报一次，松开不再报短按）
- 9~12   K1~K4 双击（松开后 300ms 内又按一下，在"第二下的按下沿"报）
- 4      KEY_ID_MAX = 物理键个数（引脚表/循环仍用 4，没变）
- 0xFF   KEY_ID_NONE

实现要点：
- key.c 里加 `key_state_t s_key[4]`：down_tick / up_tick / down / long_sent / dbl_sent。
- 新增 `key_scan()`：只比较"现在 vs 上一拍"，跑状态机，不依赖 EXTI 做边沿判断；
  扫完把电平存进 s_stable（给 key_is_pressed 用）。
- `key_entry()` 改成：按住时 10ms 轮询（长按计时），全松开时 100ms 兜底；
  有边沿中断时先 mdelay(15) 消抖再扫。
- 双击语义：第一下松开报一次短按；第二下按下沿报双击，第二下松开不再报短按。
  所以"双击"= 短按 + 双击两个事件，业务侧不要第一下就忽略 0~3 里那个编号。
- key_is_pressed() 的保护从 `id >= KEY_ID_NONE` 改成 `id >= KEY_ID_MAX`（NONE 现在是 0xFF）。
- 时间参数在 key.c 顶部：KEY_LONG_MS 800、KEY_DBL_MS 300、KEY_SCAN_MS 10。

## 修"进任务再退出就卡死"

三个 bug：

1. 【致命】`task_example.c` 的 `demo_set()` 里 `case 4: demo_close();` —— 在任务自己的线程里调 close：
   投 bye 到自己队列（自己正卡着收不到）-> `rt_sem_take(&s_exit, 3000)` 自己等自己 -> 3 秒超时
   -> `rt_mq_delete(s_q)` 删掉自己正在用的队列 -> 回循环 `rt_mq_recv` 访问已释放内存 -> 卡死。
   修：case 3/4 都只 `router_go(RT_NULL); return;`，close 一律由 router 在 kernel 线程调。
   顺带删掉 `static void demo_close(void);` 前向声明。

2. `router.c` 的 `router_dispatch()` 里 K4 拦截被删了（所有事件都直接投任务），导致按 K4 任何页面都不退。
   修：恢复 `if(msg->type==0 && msg->code==KEY_ID_4) { if(s_cur != s_home) s_want = s_home; return; }`。

3. `close()` 里 `rt_mq_send(bye)` 返回值被丢：队列满（深度 4）时退出消息丢失 -> 3 秒超时
   -> 仍 `rt_mq_delete` 活线程的队列 -> 同样崩。menu.c / task_example.c 都改成：
   发送失败先 `rt_mq_recv(...,0)` 丢一条腾位置，最多 20 次；仍失败就打印并**不删队列**；
   信号量超时也不删队列（宁可泄漏也不踩已释放内存）。

另外：`router` MSH 命令补上打印 cur / home / want（之前是空函数），排查"<<卡在谁身上>>"很有用。

## 修 RT-Thread 静态信号量重复 init 的链表破坏 bug（方案A）

现象：进进出出几次页面后串口无输出、屏幕定格。
根因：`rt_object_init()`（object.c:238）里防重复的 `RT_ASSERT(obj != object)` 在
`//#define RT_DEBUG` 下展开为空，但 291 行 `rt_list_insert_after` 是无条件的 ——
同一个静态对象 init 两次后节点自指，第三次 init 的检查循环永远回不到 head → 死循环。
Kernel 线程（优先级 9）卡死 → tshell 饿死（串口无声）+ 不刷屏（定格）。
第一次 open 正常、第二次把链表搞坏、第三次必卡。

修法（方案A，只动 task 文件，kernel/router 未改）：
- `menu.c` / `task_example.c`：`struct rt_semaphore s_exit` → `rt_sem_t s_exit`；
  open 里 `rt_sem_create`，close 里 `rt_sem_delete` + 置 NULL；线程里 `rt_sem_release(s_exit)`。
- open 改成"三建一判"：sem / mq / thread 依次创建，任一为 NULL 就统一清理
  （`rt_thread_delete` 可安全用于尚未 startup 的线程）。
- close 保留"队列满则腾位重投（20 次）"，投不进/超时都不删队列（线程还在用）。
- 两个文件按 ①数据 ②快照 ③资源 ④逻辑 ⑤线程本体 ⑥生命周期/渲染 分节，函数间留空行。
- menu.c 里重复的 `&task_example` 去掉了（之前摆了两个同样的按钮）。
- 头注释补了"为什么必须 create/delete 不能 init"的说明，防止改回去。

注意：`HAL/ADC/adc_dma.c` 早就用 `if(...)` 守卫过同一个坑，注释里写了同样的话。
以后凡是静态对象（sem/mq/mutex/event/timer）只要可能在运行期重复初始化，一律用 create/delete。

验证：7 个源文件零警告，链接通过，FLASH 148292 B (64.65%)。

## 新增 HAL/fft + HAL/wave 瘦身 + APP/wave_ana

用户要求：HAL 加 FFT（两个数组：输入采样、输出幅值，自动取长度）；
wave 只保留采样；APP 建文件返回波形的频率/幅值/直流/最高/最低。

1) `HAL/fft.h/.c`
   - `uint16_t fft_process(const uint16_t *in, uint16_t *out, uint16_t n)`
   - `FFT_RUN(in, out)` 宏：用 sizeof 自动取数组长度（in 必须是真数组，不能是指针）
   - out[] 需要 n/2+1 个；out[0]=直流，out[k]=k 倍频幅值
   - 算法：**Goertzel 逐频点**（不是 radix-2），因为正规矩 FFT 要 4KB 数组，
     违反"驱动不放缓冲"的约定；Goertzel 零缓冲，O(n^2)，N=256 约 1~2ms
   - 不依赖 libm：cos 用泰勒（6 阶），开方用整数牛顿；系数用切比雪夫递推
   - 幅值标定：输入幅值 A 的正弦 → 主频柱约等于 A（和时域码值同量纲）

2) `HAL/wave.h/.c` 只剩 `wave_capture()`（adc_capture 的薄封装），
   原来的 analyze/measure/info 结构体**全部删掉**，分析移到 APP。

3) `APP/wave_ana.h/.c`
   - `int wave_ana_run(const uint16_t *samples, uint16_t count, uint32_t rate_hz, wave_ana_t *out)`
   - wave_ana_t：vmax/vmin/vpp/dc/amp/freq_hz + 各自 *_mv 毫伏版 + valid
   - 内部 514 字节幅值缓冲（FFT_COUNT_MAX/2+1），不用调用者管
   - `wave_ana_mv(code)` 码值转毫伏

★ 踩坑记录（重要）：Goertzel 的切比雪夫系数最初写成
   `next = coef*prev1 - prev2`（用了会自我更新的 coef），导致主频算错（1000Hz → 187Hz）。
   正确写法是固定 c1：`next = c1*ck - ckm1`。
   用 Python 复刻算法 + numpy FFT 对照验证：256@8k 的 1kHz/800 → bin32、1000Hz、幅值800
   与 numpy 完全一致；512@10k 的 625Hz/1500 也一致。**以后改 FFT 一定先跑这个对照**。

验证：8 个文件编译零警告、链接通过、FLASH 157728 B（未被调用）。

## 设计器修复 + 新功能（单屏模式 / 变量池 / 一键同步 task）

### 1. 页面不显示的根因（重要）

### 3. 变量池（导入 task .c）
工具栏「导入 C 文件」→ readAsArrayBuffer + latin1（1 字节=1 字符，中文不破坏）
→ 正则只匹配**行首**声明，避免把函数参数当变量：
`/^[ \t]*(?:static|extern)?(?:const)?(?:volatile)?(u?int(8|16|32)_t|float|double|char)\s*(\*?)\s*(\w+)/gm`
识别结果塞进 `<datalist id="varpool">`，绑定形参输入框带 list 属性 → 打字/下拉都行，
选中变量自动带出类型。task_led.c 实测识别出 9 个：a b c d color is_down bright_static long_done retry。

### 4. 一键同步 task
弹窗底部两行提示 + 「同步 task（下载改好的 .c）」按钮。
用 **latin1 字节级替换**（不 decode 成 Unicode 再 encode），只动 ASCII 三处：
1) `xxx_ui_render(...)` 调用 → `<前缀>_render(<新的实参>)`（负向断言 `(?<!void\s)` 跳过函数定义）
2) `.ui_destroy = xxx` → `.ui_destroy = <前缀>_destroy`
3) `#include "ui/xxx.h"` → `<前缀>.h`
中文一个字节不动（实测 6022→6021，少的是被替换掉的参数）。

## wave_ana：识别频段改成 1 kHz ~ 30 kHz（可配）+ 高频率下的时域判形状兜底

用户要求"控制识别范围在 1k~30k"。

1) **频段 API**：`void wave_ana_set_band(uint32_t lo_hz, uint32_t hi_hz)`
   - 默认 1000 ~ 30000（宏 WAVE_ANA_BAND_LO/HI）
   - 上限超过 采样率/2 自动压下来；范围不成立返回 -2（采样率太低）
   - run() 里把频段换算成 bin 区间 k_lo/k_hi，只在这个区间找峰（顺带滤掉 50Hz 工频）

2) **采样率要求**：看 30 kHz 必须 fs >= 60 kHz，推荐 **64 kHz + 512 点**（每格 125 Hz，
   1k=bin8，30k=bin240，正好整点）。FFT_COUNT_MAX 从 512 提到 **1024**（N=1024 约 25ms）。

3) **判形状两套**（单靠谐波不够，因为 64k 采样时基频 >10.6 kHz 就没有 3 次谐波）：
   - 谐波比（准，peak*3 <= bins 时用）：h2>=0.25h1 锯齿 / h3>=0.20h1 方波 / h3>=0.083h1 三角 / 否则正弦
   - 时域兜底（谐波看不到时）：波峰因数 CF=峰值/RMS（正弦1414/方波1000/三角锯齿1732），
     三角 vs 锯齿再用"上升段与下降段平均斜率比 >2 倍"区分（锯齿一边陡一边缓）

验证（Python 复刻，64k/512）：
   1k 正弦→SINE | 5k 方/三角/锯齿全对 | 12.5k 正弦→时域SINE | 20k 方/三角/锯齿全对 |
   30k 正弦→时域SINE | 500Hz 带外→valid=0 | 静音→valid=0   （11 例全过）

已知边界：基频 > 采样率/3.2（64k 时约 20 kHz）后每周期只剩 2~3 点，锯齿/三角分不开，统一报 TRI。
另外提醒过用户：麦克风一般到不了 30 kHz，测 30k 请直接接信号源到 PB1。

踩坑：斜率比阈值一开始写 2.5 倍，20k 锯齿只有 2.2 倍判错；改 2.0 后过，30k 仍无解（理论上就分不开）。

## 设计器修复：任务骨架填充 + ui_destroy 命名 + 小数不显示的根因（%f）

### ★ 根因：这个环境里 %f 输出空字符串（用户报"页面里文字不显示"）
- 生成的 UI 代码用 `snprintf(buf, "%0.2f", (double)c)`，而链接用的是
  `--specs=nano.specs` **且没有 `-u _printf_float`** → newlib-nano 的 %f 什么都不输出
  → `buf` 是空串 → `ui_label_set(w1, "")` → 标签空白。
- 数码管那边 `CH422_Show("%5.1f", c)` 用的是 `lv_vsnprintf`，
  `LV_SPRINTF_USE_FLOAT` 默认 0（lv_conf 没改）→ 同样输出空。
- 所以 LCD 和数码管"都不显示"是同一个原因，不是页面没建起来。
- 修法（已做）：设计器对 float 绑定**不再生成 %f**，改用自动生成的
  `fmt_f2(float v, char *buf, uint16_t n)`（整数拼 "123.45"，处理 -0.x）。
- 用户侧还要改：`CH422_Show("%5.1f", c)` → `CH422_Show("%d.%d", (int)q/10, ...)`，
  或开 `LV_SPRINTF_USE_FLOAT 1` / 链接加 `-u _printf_float`。

### 任务骨架（T[]）三个 bug 一并修掉
1. `static void <prefix>_redraw(void)` 调 `<prefix>_render(...)`，但 `.render = <prefix>_redraw`
   —— 函数名对不上；现在统一成 `task_render`，直接调 `<prefix>_render(实参)`，**不再注释**。
2. `.ui_destroy = <prefix>_destroy` → 改成 `task_ui_destroy`（任务里 static 包装，
   里面调 `<prefix>_destroy()`），符合用户"static 统一 task_xxx"的约定。
3. 单屏时 `<prefix>_open` 里写了 `s_screen = 0;`，但 `s_screen` 只在 multi 时声明
   → 单屏编译不过；现在加了 `if(multi)` 守卫。
4. 其余 static 全部改名：task_open/task_close/task_post/task_thread/task_tick/task_key/task_set。

### 前缀归一化
填 `task_veml7700` 或 `task_veml7700_ui` 都能用：
base = 去掉尾部 _ui；prefix = base + '_ui'（界面文件与函数名）。
