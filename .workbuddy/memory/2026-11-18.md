## 架构现代化：kernel 只管事件，其余全模块化，接口少而厚

用户要求：kernel 只做事件响应 + 分发；其余模块化；接口数量少、每个接口功能多（不是给接口数设上限）。

### 最终模块与接口（对外函数就这些）
| 模块 | 接口 | 说明 |
|---|---|---|
| kernel.h | 3：`kernel_init(处理函数, 渲染函数)` / `kernel_post(类型,编号,值)` / `kernel_run()` | 建队列 + 绑回调 + 10ms 主循环（取事件 -> 回调 -> 渲染回调 -> lv_timer_handler） |
| app.h | 4：`app_init(首页)` / `app_handle(事件)` / `app_render()` / `app_request(应用)` | 任务线程生死、切页、事件分给 on_key/on_set；`app_request(NULL)` = 回首页 |
| event.h | 0（只有 `evt_t {type, code, value}`） | 全系统唯一事件结构，type 0=按键 1=控件 |
| ui/common.h | 控件工厂（不动） | 页面只调 ui_* |
| task/*.c | app_task_t 一张表 | setup/update/on_key/on_set/render/teardown/ui_destroy |

依赖单向：main -> kernel / app -> event.h；kernel 不认识 app（靠 kernel_init 绑回调），app 不认识 kernel（事件是调进来的）。

## 改成"一个任务一条队列"

- `app.c` 里加 `host_t { const app_task_t *task; rt_mq_t q; }`，`s_host` 就是当前任务的上下文。
- 队列在 `app_attach()` 里创建（名字用任务名，深度 4），在 `app_stop()` 里 `rt_mq_delete()`；
  `app_init()` 不再建任何队列，只记首页 + 初始化退出信号量。
- `task_entry()` 的 parameter 从 `app_task_t*` 换成 `host_t*`，从 `host->q` 收事件；
  这样队列归属跟着线程，不用全局 s_q。
- **删掉了 "切页前把队列倒干净" 的 while(rt_mq_recv(...,0)) 循环** —— 每个任务的新队列天然是空的。
- `app` 命令多打一个 `q=on/off`，能看出当前任务的队列在不在。
- 每个任务独立队列之后，"两个线程抢同一条队列"的限制就没了；要同时跑多个任务
  只用把 `s_host` 改成数组（app.h 里写了这句话），事件侧不用再动。
- 验证：9 个源文件零警告，链接通过，FLASH 154564 B (67.38%)。
