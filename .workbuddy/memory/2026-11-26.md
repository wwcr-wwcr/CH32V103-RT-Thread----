## task_dac 重写：4 波形 + 8 滑条（完成，已上板验证）

用户要求："包含 wave_gen 的所有波形，界面里滑条控制形参，所有形参都要涉及，
因波形而异，补充控件和按钮逻辑，清晰可读"。

### 结构
`User/task_dac/task_dac.c`（逻辑）+ `task_dac_ui.c/.h`（界面 + 共享状态 g_dac）

页面（320×480）：
- 标题栏 `WAVE GEN` + 右侧状态（`1000Hz 800-2500mV` / `200-2000Hz` / `STOPPED`）
- 4 个波形按钮（id 1~4，正好 = DAC_MODE_* + 1），当前波形的按钮加 3px 强调色边框
- 参数卡片 300×264，里面 **8 根滑条全部建好**，靠"位置 + 隐藏"切换，不销毁重建
- 底部 START/STOP（id 5）+ `rc N` + 提示

### 波形 → 滑条映射（s_layout[4][5]）
| 波形 | 槽位 0..4 |
|---|---|
| SINE | FREQ, LOW, HIGH |
| TRI | FREQ, LOW, HIGH, PEAK |
| SQR | FREQ, LOW, HIGH, DUTY |
| SWEEP | F START, F END, SWEEP ms, LOW, HIGH |

滑条编号 10..17（`DAC_ID_*`），范围集中在 `task_dac_ui.h` 的 `DAC_*_MIN/MAX`。

### 关键设计
1. **只在松手时下发**：工厂滑条只在 `LV_EVENT_RELEASED` 发一条 `kernel_post(TOUCH,id,value)`，
   拖动中一条都不发 → 不会每动一像素重算波形表。
2. **拖动中的实时数字**：UI 自己加 `LV_EVENT_VALUE_CHANGED` 回调（user_data = 行号），
   只改 label，不碰 g_dac。
3. **g_dac 只由任务线程写**，UI 只读；`seq` 变化时才把值同步回滑条（松手后才发生，
   不会打断拖动），所以"clamp 后的值"能自动显示回去。
4. `clamp_levels()` 保证 `hi_mv >= lo_mv + 50`，否则 `wave_gen_*` 直接 -RT_EINVAL。
5. `task_close()` 必须 `wave_gen_stop()`，否则回菜单后 PA5 还在输出。
6. 进去默认 SINE 1kHz / 800~2500mV / running=1，示波器上立刻能看到。

### 串口命令
`td` 进页 / `tdr` 重发当前参数 / `tds` 停 / `tdm [0..3]` 切波形（无参=打印状态）

## 滑条改成拖动中实时上报（60ms 节流）

用户反馈"每次滑条松手才能看见数值实在太难以操控"。

### 改动
`APP/LVGL_DEMO/LVGL_Demo.c`：
- `cb_slider_done`（只在 RELEASED 发）→ 换成 `cb_slider_live`：
  `LV_EVENT_VALUE_CHANGED` 上 **60ms 节流**，`LV_EVENT_RELEASED` 上**不节流**
  （补终值，否则拖动中途被丢的那几格会让松手停在倒数第二个值上）。
- `ui_slider_new()` 里同时注册 VALUE_CHANGED 和 RELEASED 两个事件，同一个回调。

`User/task_dac/task_dac.c`：
- 加 `static uint8_t s_quiet`，`task_set()` 里 `s_quiet=1; apply(); s_quiet=0;`
  —— 拖动中每秒十几条，115200 的 printf 一条 6ms，不静默会拖慢界面；
  但 `rc != 0` 时仍然打印，避免静默失败。

### 关键事实（以后调手感要知道）
- 触摸本身 `LV_INDEV_DEF_READ_PERIOD = 30ms` 才采一次 → VALUE_CHANGED 最多 ~33Hz，
  所以节流值小于 30ms 基本等于不节流。
- 想真更跟手，得把 `LV_INDEV_DEF_READ_PERIOD` 调小（改 lv_conf.h 后要重编 LVGL，
  用 `.workbuddy/rebuild_cfg.py`）。
- 拖动中每次上报都会 `wave_gen_*` 重启 DMA，DAC 相位跳变 → 示波器上抽动，
  松手立刻稳，属于预期行为。

### 影响面
`ui_slider_new` 是公共工厂，**所有页面的滑条**都变成拖动中上报了。
以后哪个页面在 task_set 里做重活（FFT 等），要自己再节流。

### 验证
用户确认：数字和预览曲线实时跟手、松手波形稳定。FLASH 182796 B（79.69%）。

## 预览随频率变密 + 砍掉扫频（当天最后一轮）

### 疏密映射（`cycles_of()`，最终版）
| 频率 | 周期数 |
|---|---|
| <300 Hz | 1 |
| 300~1k | 1..2 |
| 1k~3k | 2..3 |
| 3k~8k | 3..5 |
| 8k~20k | 5..9 |

三点经验：
- 低频要"很疏"（1 个周期）才有慢波的观感；
- 上限别超过 9（128 点 → 14 采样/周期），再多就是锯齿；
- 分段要缓，一次拖到底不要"炸成一片"。

正弦表从 32 点扩到 **256 点**（`PREV_TAB`）：128 个横坐标画 n 个周期时，
每点步进 = n*2，256 点表让所有 n 都落在整数索引上，不用插值。

### 扫频预览的坑（已随功能砍掉，但结论记下来）
`dinc = ((c1*2 - c0*2)*16)/128` 这种"1/16 步"定点，在起止频率接近时
（c0=2, c1=5）整数除法直接得 **0** → 频率根本不扫，看起来像等频；
再用高频端 16 周期/128 点（8 采样/周期）就糊成锯齿/方波。
以后做扫频预览，定点精度至少用 1/256，且密度封顶 12 周期。

### 需求变更：扫频不要了
用户："算了不要调频波了" → 界面从 4 屏砍成 **3 屏**（SINE/TRI/SQR），
`DAC_MODE_NUM=3`，`wave_gen_sweep` 不再被本页调用；
`g_dac` 去掉 f_start_hz/f_end_hz/sweep_ms 三个字段，
render 签名变 `render(screen, freq, lo, hi, peak, duty)`。
`tdm 3` 会提示 "mode must be 0..2"。

### 验证
三屏来回切 5 次 rc=0、无断言；`tdm 3` 被拒；FLASH 181868 B（79.29%）。
用户确认疏密"现在合适"。

## 新增 NTC 驱动 + APP 层麦克风（18:50 之后）

### BSP/adc：加 PB0 通道
`adc_input_t` 加 `ADC_PB0 = 8`，`prepare()` 里把 PB1/PB0 一起配成 AIN，
`adc_capture()` 的白名单放行 PB0。PB0 在板上没被别的外设占用（LED 用 PB3/4/5，
I2C 用 PB6/7）。

### HAL/ntc.c/.h（照本工程风格重写，不是直接搬那份旧驱动）
参考工程用 `adc_init/adc_read_avg` + `logf`，本工程没有这两个 API，
而且全工程刻意避开 libm。所以改成：
- 用 `adc_capture(ADC_PB0, buf, 16, 0)` 采 16 点取平均
- **257 点查表 + 线性插值**（索引 = code>>4，值 = 0.1℃），全程整数
  表由离线脚本按 `T = 1/(1/298.15 + ln(R/10k)/3380) - 273.15` 生成
  抽查：adc 2048→25.0℃、1203→50.0℃、3023→0.0℃
- 状态机：code≤8 短路、code≥4088 开路，都返回 `NTC_TEMP_ERR`(INT16_MIN)
- 比率测量，和 VDDA 无关（只有界面 mV 才走 vref）
- API：`ntc_read(ntc_sample_t*)` / `ntc_temp_x10()` / `ntc_resistance()`
- msh：`ntc` 打印码值/电压/电阻/温度/状态

### APP/mic_ana.c/.h（新）
HAL/mic 只有"读一个点/采一帧/峰峰值"，这里补应用层：
- 静态 8KB 缓冲 `s_buf[4096]`（aligned(2048)，@8kHz = 512ms）
- `mic_ana_capture(n, rate)` / `mic_ana_buf()` / `mic_ana_count()`
- `mic_ana_stats()`：直流、峰峰、单边峰值、RMS（64 位平方和 + 牛顿迭代开方）、
  带迟滞的过零计数 → 单音频率估计、0~100 声级、削顶百分比
- `mic_ana_play()`：原地把码值转成 int16（减直流）交给 `speaker_play`，录音回放
- msh：`micana [n]` / `micrec [ms]` / `micplay`
