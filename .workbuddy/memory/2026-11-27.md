
## 构建工具：MRS 自带 make（终于不用手搓链接命令）

- make:  `C:/MounRiver/MounRiver_Studio3/resources/app/resources/win32/others/Build_Tools/Make/bin/make.exe`
- gcc:   `.../components/WCH/Toolchain/RISC-V Embedded GCC/bin`
- 用法:  `cd obj && make -j4 all`（PATH 里要有上面两个目录）
- 产物:  `obj/CH32V307-RT-Thread.elf`（和 MRS Build 同一个文件）
- 封装成了 `.workbuddy/build.py`（增量/clean 两种）

坑：
1. obj/*/subdir.mk 由 MRS 从工程文件生成，**删掉的任务目录会残留** →
   `No rule to make target '../User/xxx/xxx.c'`。要删 obj 里对应子目录 + makefile 里的 -include 行。
2. 新加的任务如果没在 MRS 里 F5，makefile 里**没有它的 -include** → 不参与编译。
   这次手工补了 `obj/User/task_ntc/subdir.mk`（从 task_menu 的复制改路径）。
3. 手搓 gcc 链接时 `-T "c:\...\Link.ld"` 和 `-Wl,-Map,"x.map"` 里的引号/反斜杠会让
   ld 报 "Invalid argument"；用 make 就没这些事。

## 串口号会变！
WCH-Link 重新枚举后从 **COM5 变成 COM7**（COM3/COM5 变成了蓝牙串口）。
读串口前先 `[System.IO.Ports.SerialPort]::GetPortNames()` + 查 `WCH-Link SERIAL (COMn)`。

## NTC 任务（用用户自己写的 ntc.c）

用户把 HAL/ntc.c 换成了自己的一版：`ntc_init()` + `ntc_get_temperature()`
（`adc_capture(ADC_PB0, samples, 16, 0)` + logf 算 B 值）。

**实测正常：24.2℃ 稳定**。说明 `adc_capture` 的单点/全速路径其实是好的，
之前我判"BSP 单点 DMA 不可靠"是错的 —— 真正原因是**我的驱动自己 ADC_DeInit 抢 ADC1**，
和 BSP 的 prepare() 缓存打架。教训：不要在驱动里重复初始化别人的外设。

任务侧（`User/task_ntc/task_ntc.c`）：
- task_tick 里 500ms 节流调 `ntc_get_temperature()`（原来是每 10ms 一次，白占 ADC）
- task_render 把 `a` 传给 `task_ntc_ui_render(a)`
- K1 立刻重采
- 调试命令：`ntct` 进页面、`ntcp` 现读一次

界面（`task_ntc_ui.c`）：16px 大字温度 + 4 行参数说明，INT32_MIN 显示 "--.- C"。

构建：FLASH 180244 B（78.58%），RAM 74700 B（75.99%）。
